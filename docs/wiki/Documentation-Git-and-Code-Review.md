# Documentation, Git and Code Review

## Why documentation matters

Good documentation helps other developers understand the purpose, structure, and decisions behind the code.

## Git basics

Common commands:

```bash
git status
git add .
git commit -m "Add project documentation"
git push
```

## Code review

Code review helps catch problems such as:

- poor naming
- weak validation
- unclear responsibilities
- missing comments or tests

## Naming conventions

Use names that explain purpose.

Examples:

- `BorrowBook()` instead of `DoThing()`
- `BookTitle` instead of `x`
